아이디·비밀번호·닉네임으로 가입하면 투자금 **1,000만 원**이 지급됩니다. 로그인, 계좌, 주문과 관심 종목은 서버에서 관리합니다.

- 기업 **26개**, ETF **8개**: 금융지주·보험·증권·지주·바이오·제약·클라우드·반도체·게임·항공·조선·방산·리츠 등

- 매일 한국 시간 **16:40–23:40**, 단일가 체결(2026-10-20 21:00 KST 전 10분, 이후 5분). **2026-10-19만 20:00–23:40** 특례

- 금리·환율·원유·금 가격과 업종별 사업 구조가 시세에 반영, 오늘·1주·1개월 추이 그래프
- 상승·조정·순환 국면, 3~5일 간격 산업 사건과 조건 변경 후속 기사, 실적·계약 뉴스의 이틀간 잔존 효과
- 종목별 난수 상관을 줄이고 장기 성장 경향과 업종·기업별 차이를 분리; 과거 가격·계좌는 유지
- 기업 실적·계약·공급망·원자재·금리·배당 등 **18개 뉴스 분야**, 비교 수치와 상세 기사, 검색·분야 필터·발표 일정

## 거래 제도

주식은 전일 기준가의 ±30%, 2배 ETF는 ±60%의 가격 제한을 적용합니다. 주식 가격대별 호가 단위는 1·5·10·50·100·500·1,000원입니다. ETF는 2,000원 미만 1원, 그 이상 5원입니다. 시장 시간은 이 서비스가 정한 시간이며 실제 거래소 운영 시간과 다릅니다.

다음 단일가에서 조건을 충족한 주문을 시장가, 가격, 접수 시간 순으로 배분합니다. 매 회차 순수요에 대해 주식 800주, ETF 1,500주까지 시장조성 물량을 공급하며, 나머지 잔량은 다음 회차로 이월합니다. 마지막 회차 23:40 체결 후 미체결 잔량은 만료됩니다. 1회 최대 2,000주, 계정당 미체결 30건, 분당 주문 12건입니다.

수수료는 매수·매도 각각 0.1%, 체결 건별 원 미만 올림입니다. 부분 체결 수수료에 필요한 금액을 확보하도록 매수 주문은 `수량 × (주문 상한 가격 + 주당 수수료 올림값)`으로 담보를 확보하고, 체결 후 차액과 취소 잔량의 담보를 돌려줍니다. 즉시 결제하며 신용·공매도·세금은 구현하지 않았습니다.

배당주는 매일 23:20 권리 확정·배당락, 23:40 지급입니다. 리츠는 19:20 확정·19:40 지급이 추가되어 하루 2회입니다. 권리 확정 회차의 주문을 체결하기 직전 보유량이 기준이므로, 그 회차에 배당락 가격으로 새로 매수한 수량에는 배당하지 않습니다. 회당 배당액과 다음 일정은 종목 배당 탭에 표시합니다. 배당락 시 가격 기준을 조정하고, 미수 배당금과 실제 입금은 권리별 한 번만 정산합니다. 무배당 성장주의 정책은 유지합니다. 이는 서비스가 정한 단축 배당 일정입니다.

ETF는 자산별 지수·금리·금과 환율에 연동됩니다. 일일 배수와 장기 누적 수익률은 다를 수 있습니다. 비용은 표시된 연간 비용을 일할 계산하고, 참여자 수요가 시장가격과 NAV의 괴리에 반영됩니다.

## 기업과 정보 채널

`/companies/종목코드`에서 각 기업의 슬로건·제품·강점·사업 구성·재무 지표·뉴스를 확인합니다. 기업 뉴스룸의 기사는 터미널의 뉴스 & 인사이트 원문으로 연결됩니다. 종목의 물음표에서도 기업 설명과 홈페이지로 이동할 수 있습니다.

정보 라운지는 회원 게시글과 미확인 제보를 제공하는 커뮤니티, 발표 자료와 기업 수치를 대조하는 구독 리서치로 구성됩니다. 자동 제보는 봇 작성자로 표시하며, 회원은 글을 게시하고 본인 글을 삭제할 수 있습니다. 리서치는 출처·기준 시점·비교 지표·EPS 시나리오를 제공합니다. 상승·하락 판정이나 비공개 가격 생성값은 제공하지 않습니다.

리서치 패스는 **게임 내 계좌 잔액 50만 원으로 24시간** 이용하며 자동 갱신하지 않습니다. 실제 결제는 없습니다. 서버에서 유효한 구독을 확인한 뒤에만 기사 전문을 반환합니다. 공개 목록·게임 API에는 전문이 포함되지 않습니다. SQL 트리거가 사용 가능한 현금 차감·구독 활성화·지출 원장을 함께 처리하고, 요청 키로 중복 차감을 방지합니다.

리서치 패스는 새 구독마다 50만 원이 적용됩니다. 아래의 2026-10-19 시작 데이터 초기화에서는 기존 구독도 함께 초기화합니다.

노동은 장 운영 시간과 관계없이 로그인 후 이용합니다. `/api/work`가 순차적인 터치를 한 번씩 기록하며, 누적 100회마다 SQL 트리거가 1,000원 입금과 노동 수당 원장 기록을 함께 처리합니다. 요청 키·진행 순서·최소 처리 간격으로 재시도와 동시 요청에 따른 중복 지급을 막습니다. 클라이언트가 보낸 수량이나 보상 금액으로 계좌를 변경하지 않습니다.

노동 수입은 **한국 시간 00:00~다음 날 00:00에 최대 50,000원**입니다. SQL 트리거가 해당 날짜에 실제 지급된 노동 수당 원장을 확인하므로 기기 변경·동시 요청·계좌 지출로 한도를 우회하지 못합니다. 같은 날 이미 받은 수당도 포함하고, 과거 잔액은 회수하지 않습니다. 자정에 한도만 초기화하고 누적 수입과 미완료 터치 진행률은 유지합니다. 노동 화면은 오늘 수입·남은 한도·초기화 시각을 표시하고 자정 및 다시 화면을 볼 때 갱신합니다.

전체 튜토리얼은 A–Z 26단계를 6개 주제로 묶었습니다. 단계에 맞춰 종목·지표 탭·정보 채널을 표시하고 화면 위치를 강조합니다. 목차 검색·이전/다음·처음부터·직접 살펴보기를 지원하며, 닫아도 같은 브라우저에서 계정별 마지막 위치를 이어봅니다. 주문·구독·노동을 자동 실행하지 않으며, 완료 시 기존 계정의 튜토리얼 완료 표시를 저장합니다.

## 구현과 데이터 보존

React / Vinext / TypeScript, Cloudflare Workers + D1(SQLite). GitHub에는 소스를 보관하고 위 주소에서 서버를 운영합니다. GitHub Pages 단독으로 로그인·공유 시장을 실행하지 않습니다.

비밀번호는 개별 솔트와 scrypt(N=16384, r=8, p=5)로 해시합니다. 세션 토큰은 256비트 난수이며 해시만 DB에 저장합니다. 쿠키는 `__Host-`, HttpOnly, Secure, SameSite=Lax를 사용합니다. 로그인 속도 제한, Origin 검사, 세션 만료·로그아웃·비밀번호 변경 시 세션 폐기를 적용합니다. 기존 ChatGPT 로그인은 사용하지 않습니다.

계좌와 체결은 SQL 트리거와 원자적 배치로 정합성을 보장합니다. revision 검증과 고유 회차·주문 키로 동시 정산과 재시도에 의한 중복 체결을 차단합니다. 빠진 회차는 서버 시간이 정한 경계로 복원합니다. GitHub Actions의 주기 요청은 지연될 수 있지만 서버가 누락 회차를 정산합니다.

2026-10-19 요청으로 전체 게임을 시작 상태로 한 번 초기화합니다. 아이디·비밀번호·닉네임·로그인 세션은 유지하고, 모든 계좌는 현금 1,000만 원으로 돌아갑니다. 주식·주문·체결·배당·관심 종목·노동·구독·게시글·시세 기록을 초기화한 뒤 시작 종목과 기사를 생성합니다. `reset_version`을 확인하는 단일 트랜잭션으로 실행하므로 새 배포·새로고침·동시 요청으로 초기화가 반복되지 않습니다. SQL 마이그레이션은 열 추가만 수행하고 데이터 초기화는 서버의 일회성 작업으로 분리합니다.

이미 적용한 마이그레이션은 보존합니다. `0007`은 발행 커서와 초기화 완료 표시를 추가합니다. 최초 초기화가 끝난 뒤에는 같은 프로젝트에 배포해도 게임 데이터가 유지됩니다. 오늘의 특례는 한국 날짜로만 판정하며 10월 20일부터 16:40 개장으로 자동 복귀합니다.

무인 갱신은 공개된 `/api/heartbeat`를 사용합니다. 이 경로는 입력 없이 서버 현재 시각까지의 작업만 처리하고 재호출은 중복 글을 만들지 않습니다. GitHub Actions가 하루 종일 5분마다 호출하며, 지연된 발행은 서버가 순서대로 복원합니다. 일반 뉴스와 커뮤니티는 글마다 시각 기반 고유 ID를 사용하고 리서치는 원문별로 한 번만 발행합니다. 주기 작업은 소스를 재배포하지 않습니다.

## 검증

Node.js 24 권장, 의존성은 `pnpm-lock.yaml`에 고정되어 있습니다.

```sh
corepack pnpm install --frozen-lockfile
node node_modules/typescript/bin/tsc --noEmit
node --experimental-strip-types --test tests/*.test.mjs
node tests/runtime-smoke.mjs
```

단위·거래 테스트는 실제 SQL 마이그레이션과 트리거를 사용합니다. 런타임 검증은 격리된 Workers / D1에서 실제 API 핸들러의 인증·주문·체결·튜토리얼·커뮤니티·구독 차감·재시도·유료 기사 접근 권한을 확인합니다. 운영 DB에 테스트 계정을 만들지 않습니다.
